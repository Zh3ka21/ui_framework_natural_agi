# Фреймворк вводу рукописних символів з live-класифікацією

Тема роботи: *Розробка фреймворку вводу рукописних цифр.*

Мета: веб-інтерфейс, де користувач малює цифру або букву на полотні, а система **на кожен дотик до полотна**
(не по кнопці) показує, що вона розпізнала. Спочатку бекендом є звичайна CNN, яку ти тренуєш локально. Пізніше
CNN замінюється на графовий пайплайн NaturalAGI — контракт запиту/відповіді при цьому не змінюється.

Проєкт NaturalAGI (Docker, Kafka, Neo4j) для цього етапу **не потрібен**. Усе в пакеті працює на будь-якому ноутбуці
з Python 3.10+, без GPU.

## 1. Що в пакеті

```
ui_puzanov/
├── GUIDE.md            цей файл
├── requirements.txt
├── train_cnn.py        тренує CNN на EMNIST-letters (26 букв) або MNIST (10 цифр), зберігає models/cnn_*.pt
├── preprocess.py       полотно -> 28×28 у форматі EMNIST. Єдине місце, де це робиться
├── server.py           FastAPI: віддає сторінку і POST /predict
├── static/index.html   полотно, надсилання на кожен рух, top-k стовпчики, прев'ю 28×28
└── models/
    ├── cnn_letters.pt  вже натренована (5 епох, 94.9% на тесті EMNIST-letters) — можна не тренувати
    └── cnn_digits.pt   вже натренована (3 епохи, 99.5% на тесті MNIST)
```

## 2. Запуск за 3 хвилини

```bash
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python server.py --model models/cnn_letters.pt        # відкрити http://127.0.0.1:8000
```

Для цифр: `python server.py --model models/cnn_digits.pt --port 8001`.

Перетренувати модель (не обов'язково; EMNIST-архів 560 МБ качається один раз):

```bash
python train_cnn.py --dataset letters --epochs 5
python train_cnn.py --dataset digits  --epochs 3
```

На CPU одна епоха EMNIST — 1–2 хвилини. Якщо ноутбук слабкий, тренуй у Google Colab і скопіюй `.pt` у `models/`.

## 3. Як це працює

**Полотно** (`static/index.html`). Білий штрих на чорному тлі, `pointer`-події (миша, тачпад, стилус, палець).
На `pointerdown`, кожен `pointermove` і `pointerup` викликається `requestPredict()`.

**Правило реального часу.** У польоті не більше одного запиту. Якщо під час очікування відповіді прийшли нові рухи,
після відповіді надсилається рівно один новий запит з актуальним станом полотна. Так інтерфейс ніколи не відстає
і не завалює сервер чергою. Це важливіше за будь-який throttle по таймеру.

**Препроцесинг** (`preprocess.py`). Модель тренована на EMNIST, тому все намальоване має пройти той самий шлях,
що й EMNIST-зображення: чорнило яскраве на чорному тлі → обрізка по bounding box чорнила → квадрат з полем ~12% →
resize до 28×28 з антиаліасингом → легкий blur. Якщо пропустити хоч один крок, модель бачить розподіл, якого не
вчила, і відповіді стають випадковими. У UI є прев'ю 28×28 «що бачить модель» саме для того, щоб це контролювати.

**Сервер** (`server.py`). Контракт:

```
POST /predict
{ "image": "data:image/png;base64,...", "topk": 3 }

200
{ "empty": false, "label": "B",
  "candidates": [ {"label":"B","prob":0.97}, {"label":"R","prob":0.01}, ... ],
  "preview": [[0..255 × 28] × 28],
  "ms": 1.6 }
```

Час однієї відповіді CNN на CPU — 1–3 мс; повний цикл у браузері — 10–30 мс. Це і є ціль: «живе» оновлення без
помітної затримки.

## 4. Завдання по етапах

1. **Запустити як є**, переконатись, що при малюванні результат оновлюється на кожен рух. Помалювати 26 букв і 10
   цифр, записати, які плутаються. Очікувано: I/L (у EMNIST велике I і мале l злиті в один клас), O/Q, G/Q, D/O.
2. **Довести UI до фреймворку.** Зробити з index.html нормальний застосунок: режим букви/цифри перемикається
   без перезапуску сервера (два моделі завантажені одразу, параметр у запиті), товщина штриха, undo, гаряча
   клавіша очистки, робота на телефоні. Історія останніх розпізнавань. Збереження намальованих зразків у папку
   з міткою, яку підтверджує користувач: це дасть нам власний маленький датасет «рукопис з полотна».
3. **Виміряти затримку** від події `pointermove` до оновлення екрана і показати її в інтерфейсі. Порівняти два
   варіанти: (а) запит на сервер, (б) модель у браузері через ONNX Runtime Web (експорт `torch.onnx.export`).
   Варіант (б) прибирає сервер узагалі і цікавий для захисту.
4. **Підключення NaturalAGI.** Коли графовий пайплайн буде доступний за HTTP-адресою, замінити функцію `predict()`
   у `server.py` на виклик пайплайна. Контракт відповіді той самий плюс нове поле: граф скелета (вузли, ребра)
   і концепт-переможець, щоб малювати їх поруч із полотном. Це і є «пояснюваність», заради якої проєкт існує.
   Деталі контракту узгодимо на етапі 4; препроцесинг для пайплайна відрізняється (він приймає 100×100), тому в
   `preprocess.py` з'явиться друга функція.

## 5. Що здати

- Репозиторій фреймворку з інструкцією запуску в одну команду (README) і `requirements.txt`.
- Демонстрація: людина малює, система відповідає наживо, з перемиканням букви/цифри.
- Таблиця затримок (сервер vs браузер), на якому залізі.
- Папка зібраних власних зразків з мітками, якщо етап 2 дійшов до збереження.
- Звіт 2–4 сторінки: архітектура, препроцесинг (з картинками «до/після»), вимірювання, що плутається і чому.

## 6. Типові помилки

- Чорне чорнило на білому тлі без інверсії. Модель вчила білі штрихи на чорному.
- Надсилати запит по таймеру замість «один у польоті»: або лаг, або черга.
- Змінювати препроцесинг в UI, а не в `preprocess.py`: потім сервер і тести бачать різне.
- Малювати тонким штрихом на великому полотні: після стиску до 28×28 лінія зникає. Товщина штриха ≈ 1/16 полотна.
- Тестувати «точність» на власних малюнках і робити висновки про модель: це інший розподіл, ніж EMNIST.
